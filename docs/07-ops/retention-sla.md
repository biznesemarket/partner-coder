# Retention и SLA

Статус: предложение к подтверждению. Дата: 2026-11-19.

## 1. Хранение данных

| Данные                   | Срок                                                  |
| ------------------------ | ----------------------------------------------------- |
| Сырые heartbeat          | 90 дней, затем агрегируются                           |
| Интервалы и закрытые дни | Пока действует договор                                |
| Аудит                    | Не менее 3 лет                                        |
| Счета и платежи          | По налоговому/договорному сроку; уточняет бухгалтерия |
| Пакеты                   | 30 дней после активации или истечения                 |
| Персональные данные      | Удаление через 30 дней после окончания договора       |
| Резервные копии          | 30 дней daily + 12 месяцев monthly (предложение)      |
| Логи приложений          | 30 дней                                               |
| Метрики                  | 90 дней                                               |

Исключения: данные, обязательные к хранению по закону, и обезличенные
агрегаты.

## 2. Резервное копирование и восстановление

Предложение:

- RPO — 15 минут (непрерывная архивация WAL в S3).
- RTO — 4 часа.
- Ежедневный full backup.
- Хранение: 30 дней daily, 12 месяцев monthly.
- Restore drill — не реже одного раза в квартал.
- Проверка цепочек аудита после восстановления.

## 3. Доступность

Предложение для MVP:

- Целевая доступность — 99,5% в месяц, без плановых работ.
- Плановые работы — с уведомлением не менее чем за 24 часа.
- Аварийные работы — без предварительного уведомления, с публикацией статуса.

## 4. Поддержка

| Параметр             | Предложение                             |
| -------------------- | --------------------------------------- |
| Каналы               | `support@pcoder.ru`, позже Telegram/MAX |
| Часы                 | Пн–Пт, 10:00–19:00 МСК                  |
| Критический инцидент | Реакция до 4 рабочих часов              |
| Обычный запрос       | Реакция до 1 рабочего дня               |
| Плановый вопрос      | До 2 рабочих дней                       |
| Статус-страница      | Позже, в M9                             |

Критический инцидент: недоступность Сервиса, потеря данных, утечка, ошибка
биллинга, блокировка входа.

## 5. Уведомления об инцидентах

- Внутренний канал: Telegram или MAX, создаётся при настройке сервера.
- Критические алерты получает владелец и технический администратор.
- Сроки уведомления клиентов и регулятора уточняет юрист по 152-ФЗ.

## 6. Мониторинг

- `/healthz`, `/readyz` API.
- Метрики API и worker.
- Ошибки 5xx, latency, очередь pg-boss, диск, соединения PostgreSQL.
- Проверка backup и WAL.
- Алерты: сначала Telegram/MAX, позже email/телефон.

## 7. Открытые вопросы

1. Подтвердить RPO 15 минут и RTO 4 часа.
2. Подтвердить SLA 99,5%.
3. Подтвердить часы поддержки и сроки реакции.

6. Выбрать канал алертов: Telegram или MAX.
