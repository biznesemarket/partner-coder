# ADR-0007: Закрытие дня, неизменяемость, компенсации

| Поле   | Значение   |
| ------ | ---------- |
| Статус | принято    |
| Дата   | 2026-11-15 |

## Контекст

Начисления — финансовые обязательства. Перезапись закрытого дня разрушает
доверие: разработчик видел одну сумму, директор — другую. При этом события
могут приходить позже (offline), а ошибки расчета надо исправлять.

## Решение

- Закрытый `day_record` неизменяем: запрет UPDATE/DELETE на уровне прав и
  триггеров; append-only.
- Повторный расчет с теми же входами идемпотентен: сравнивается `input_hash`.
- Изменившийся расчет создает `day_adjustment` на дельту от эффективной
  суммы (база + корректировки), с детерминированным id: повтор не дублирует
  компенсацию.
- Эффективная сумма = база + сумма корректировок; дайджест и дашборд
  показывают эффективную сумму.
- Закрытие выполняет worker по расписанию `close_at` в поясе проекта;
  пропущенные дни догоняются при следующем запуске.
- Поздние события в пределах `late_grace_hours` принимаются и создают
  компенсацию; дальше — `late_rejected` до решения директора.

## Последствия

- Плюс: аудируемая история, споры решаются дельтой, а не перезаписью.
- Минус: UI обязан показывать базу, корректировки и эффективную сумму.
- Минус: компенсации требуют детерминированных id, иначе возможны дубли.

## Альтернативы

- Пересчет с версионированием строк: сложнее аудит и права.
