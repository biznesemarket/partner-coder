# ADR-0008: Git-провайдеры и метаданные

| Поле   | Значение   |
| ------ | ---------- |
| Статус | принято    |
| Дата   | 2026-11-15 |

## Контекст

Нужно подтверждать результат работы, не храня код. Провайдеров несколько:
GitHub, GitLab, Gitea/Forgejo; часть клиентов работает без git.

## Решение

- Провайдер-абстракция: `install`, `repos`, `webhooks`, `facts`, `health`.
- GitHub — через GitHub App (установка, выбор репозитория, webhook secret),
  события push/PR/issues.
- GitLab и Gitea/Forgejo — минимум вебхуков и API backfill в MVP.
- Принимаются только метаданные: ветки, коммиты, PR, задачи, метки, автор,
  время. Содержимое файлов, диффы и код не сохраняются.
- Вебхук: HMAC сырого тела, сравнение с постоянным временем, дедупликация по
  `delivery_id`.
- Сессии связываются с фактами по ветке/задаче; пустые поля заполняются.
- `no_output` ставится, если оплачено больше порога при нулевых результатах.
- Режим «без git» допустим: онбординг пропускает git, `no_output` отключен,
  проект помечается явно.

## Последствия

- Плюс: подтверждение результата без хранения интеллектуальной собственности.
- Минус: лимиты API и различия провайдеров требуют диагностики и backfill.
- Минус: связывание по ветке/задаче эвристическое — нужны флаги и споры.

## Альтернативы

- Хранить диффы для оценки: нарушает границу приватности.
