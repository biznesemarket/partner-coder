# ADR-0006: Аутентификация, роли, RLS

| Поле   | Значение   |
| ------ | ---------- |
| Статус | принято    |
| Дата   | 2026-11-15 |

## Контекст

В системе четыре контура доступа: суперадминистратор вендора, финансы и
поддержка вендора, директор клиента, разработчик. Данные разных tenant
изолированы. Опасные действия (выплаты, политика, споры) требуют
дополнительного подтверждения.

## Решение

- Better Auth: email OTP и magic link, passkeys, 2FA; self-hosted.
- Суперадминистратор: passkey/TOTP обязательны, короткая сессия, IP allowlist,
  повторная проверка для опасных действий.
- Директор: magic link; приглашения одноразовые, TTL.
- Разработчик: magic link из приглашения + device token (Ed25519).
- Агент: 256-битный токен, в БД только хеш; scope tenant/participant/device;
  отзыв и ротация.
- Авторизация: матрица «роль × ресурс × действие»; отказы пишутся в аудит.
- Изоляция: RLS + `SET LOCAL app.tenant_id`; tenant берется только из
  сессии/токена.

## Последствия

- Плюс: нет внешнего identity-вендора; соответствие требованию хостинга в РФ.
- Минус: нужно самим сопровождать passkeys, восстановление доступа и 2FA.
- Минус: тесты authz обязаны покрывать каждый ресурс × каждую роль × чужой tenant.

## Альтернативы

- Внешний IdP (Auth0/Keycloak): зависимость и данные за рубежом.
