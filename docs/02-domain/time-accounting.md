# Учет времени с ИИ-агентом

| Поле      | Значение                                                      |
| --------- | ------------------------------------------------------------- |
| Код       | DOMAIN-TIME                                                   |
| Версия    | 2.0 (TypeScript)                                              |
| Статус    | Нормативный документ; реализация — `packages/domain/src/time` |
| Заменяет  | POLICY-TIME v0.1 (Python-проект)                              |
| Связанные | ADR-0003, ADR-0007, `economics.md`, `calculator.md`           |

## 1. Назначение

Определить, какое время считается рабочим, как оно оплачивается и как
превращается в долю. Документ нормативный: два независимых читателя обязаны
получить одинаковый результат по сценариям §9.

## 2. Событие активности (heartbeat)

Агент отправляет событие каждые `heartbeat_interval_sec` (по умолчанию 30):

| Поле            | Описание                                                         |
| --------------- | ---------------------------------------------------------------- |
| `event_id`      | UUID, идемпотентность                                            |
| `session_id`    | сессия работы                                                    |
| `membership_id` | человек-владелец                                                 |
| `project_id`    | проект                                                           |
| `seq`           | монотонный номер устройства                                      |
| `received_at`   | **серверное** время приема — авторитетное                        |
| `client_time`   | часы клиента, только для флага `clock_skew`                      |
| `agent`         | `attached`, `running`, модель                                    |
| `signals`       | `input_events`, `scroll`, `files_touched`, `tool_calls`, `focus` |
| `signature`     | подпись Ed25519 (сервер проверяет)                               |

Расхождение часов клиента больше `max_clock_skew_sec` (300) ставит флаг
`clock_skew`, но не меняет расчет. Сессия обязана иметь `task_ref` и `branch`:
без привязки время учитывается, но не оплачивается (флаг `no_task_link`).

## 3. Классы времени

| Класс              | Условие                                                                            | Коэффициент          |
| ------------------ | ---------------------------------------------------------------------------------- | -------------------- |
| `active_human`     | ввод/навигация за последние `active_window_sec` (120)                              | 1,0                  |
| `supervised_agent` | ввода нет, присутствие подтверждено за `presence_window_sec` (600), агент работает | `k_supervised` (1,0) |
| `autonomous_agent` | агент работает, присутствия человека нет                                           | `k_autonomous` (0,2) |
| `idle`             | нет активности человека и агента дольше `idle_timeout_sec` (300)                   | 0                    |

Присутствие человека — любой сигнал (клавиатура, мышь/скролл, смена файла,
фокус, ответ агенту) в окне присутствия. Присутствие без запущенного агента
классифицируется как ручная работа: класс `active_human`, но оплата зависит
от `manual_only_policy` (см. §6).

Интервал между двумя событиями кредитуется не дольше `idle_timeout_sec`:
остаток считается простоем. Это защищает от «offline-накрутки».

## 4. Формулы и порядок применения

Порядок строго детерминирован (реализация: `calculateDay`):

1. Классифицировать интервалы.
2. Объединить пересекающиеся интервалы человека (union), не суммировать.
3. Разрезать по границе локальных суток и по смене версии ставки.
4. `paid_seconds = active + supervised × k_supervised + autonomous × k_autonomous`.
5. Применить кап автономного класса: `autonomous_paid ≤ autonomous_paid_cap_hours`.
6. Применить дневной кап: `total_paid ≤ daily_cap_hours`.
   Приоритет усечения: `active_human` → `supervised_agent` → `autonomous_agent`
   (сначала сохраняется активная работа человека, затем супервизия).
7. `amount_kopecks = ROUND_HALF_UP(paid_seconds × rate_kopecks_per_hour × k_quality / 3600)`.
8. Дальше — экономика дня (`economics.md`).

Все вычисления — в целых секундах, копейках и базисных пунктах; float в
деньгах и долях запрещен.

### 4.1 Капы и усечение

- Автономный кап применяется к **взвешенным** секундам автономного класса.
- Дневной кап применяется после автономного, к сумме всех оплачиваемых классов.
- Усеченные секунды распределяются по отрезкам дня пропорционально их
  исходному вкладу в класс, поэтому смена ставки внутри дня не искажает сумму.
- Усечение отражается флагами `cap_applied` и `autonomous_cap_applied`.

### 4.2 Смена ставки внутри дня

Интервалы режутся по моментам `effective_from` версий ставки. Каждый отрезок
оплачивается по своей ставке, но округление выполняется один раз на весь день.

Пример T-06: 5 ч по 500 ₽ + 1 ч по 600 ₽ = 3 100 ₽.

### 4.3 Полночь и часовые пояса

Граница суток — 00:00 пояса проекта (`project.timezone`, по умолчанию
`Europe/Moscow`). Сессии через полночь режутся; сутки при переходе DST могут
длиться 23 или 25 часов. События хранятся в UTC.

## 5. Union и запрет двойной оплаты

- Пересекающиеся интервалы одного человека объединяются (union).
- При пересечении разных классов побеждает старший класс:
  `active_human` > `supervised_agent` > `autonomous_agent` > `idle`.
- Один и тот же отрезок времени никогда не оплачивается дважды
  (инвариант 6). Union не создает «пустых» отрезков между интервалами.

## 6. Работа без агента

| `manual_only_policy`        | Поведение                                                           |
| --------------------------- | ------------------------------------------------------------------- |
| `track_only` (по умолчанию) | учтено в `trackedSeconds`, 0 ₽, флаг `manual_track_only`            |
| `ignore`                    | не учитывается                                                      |
| `bill`                      | зарезервирован: возвращается 422 `manual_only_policy_not_supported` |

## 7. Опоздавшие события и offline

Агент буферизует события локально и отправляет при связи.

| Ситуация                           | Поведение                                      |
| ---------------------------------- | ---------------------------------------------- |
| Задержка ≤ `late_grace_hours` (24) | принимается; если день закрыт — компенсация    |
| Задержка > грейса                  | флаг `late_rejected`, 0 ₽ до решения директора |
| Прием после закрытия суток         | дополнительно флаг `late_arrival`              |

Закрытый день не перезаписывается (ADR-0007). Повтор с теми же входами
идемпотентен по `input_hash`; изменившийся пересчет создает компенсацию на
дельту от эффективной суммы.

## 8. Антифрод: флаги дня

| Флаг                             | Условие                                                                                        |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| `no_output`                      | оплачено больше `no_output_flag_hours` (3) при нулевых коммитах, диффах и вызовах инструментов |
| `synthetic_input`                | интервалы ввода без вариативности (эвристика)                                                  |
| `night_autonomous_spike`         | автономный класс ночью (22:00–06:00) больше `night_autonomous_flag_hours` (6)                  |
| `clock_skew`                     | расхождение часов клиента больше порога                                                        |
| `replay`                         | повтор `event_id` или нарушение `seq`; **отменяет начисление**                                 |
| `no_task_link`                   | сессия без задачи/ветки                                                                        |
| `cap_applied`                    | применен дневной кап                                                                           |
| `autonomous_cap_applied`         | применен кап автономного класса                                                                |
| `pending`                        | пул исчерпан                                                                                   |
| `late_rejected` / `late_arrival` | поздние события                                                                                |
| `manual_track_only`              | работа без агента учтена, но не оплачена                                                       |

Флаг не меняет формулу (кроме `replay`) и попадает в дайджест директора.

## 9. Приемочные сценарии

Базовые условия: ставка 500 ₽/ч, оценка 10 000 000 ₽, дневной кап 12 ч,
`k_supervised` 1,0, `k_autonomous` 0,2, автономный кап 2,0 ч.

| #    | Вход                                                 | Ожидание                               |
| ---- | ---------------------------------------------------- | -------------------------------------- |
| T-01 | active 4 ч, supervised 2 ч, autonomous 3 ч, idle 1 ч | 6,6 оплач. ч → 3 300 ₽ → 0,0330 %      |
| T-02 | ночь: только autonomous 8 ч                          | 1,6 оплач. ч (кап 2,0) → 800 ₽         |
| T-03 | active 10 ч + supervised 4 ч                         | кап 12 ч → 6 000 ₽, флаг `cap_applied` |
| T-04 | сессии 10–12 и 11–13                                 | union 3 ч, не 4 ч                      |
| T-05 | сессия 22:00–02:00                                   | день D: 2 ч; D+1: 2 ч                  |
| T-06 | ставка 500 до 14:00, 600 после; active 09–15         | 5×500 + 1×600 = 3 100 ₽                |
| T-07 | простой 20 мин                                       | 0 ₽ за интервал                        |
| T-08 | offline 3 ч, загрузка через 5 ч                      | учтено в грейсе, компенсация           |
| T-09 | offline 30 ч                                         | `late_rejected`, 0 ₽ до решения        |
| T-10 | работа без агента 4 ч                                | `track_only`: учтено, 0 ₽              |
| T-11 | T-01 + `k_quality` 1,1                               | 3 630 ₽                                |
| T-12 | autonomous 12 ч                                      | кап 2,0 ч → 1 000 ₽                    |

Числа закреплены фикстурами `packages/domain/fixtures/golden/scenarios.json`
и тестом `packages/domain/src/golden.test.ts`.
