# Варианты лицензии публичного репозитория

Статус: предложение для решения с юристом. Дата: 2026-11-19.
Текущий `LICENSE` — временная source-available формулировка.

## 1. PolyForm Shield 1.0.0

**Что разрешает:** смотреть, изучать, форкать и изменять код для
неконкурентного использования.

**Что запрещает:** использовать код для продукта, который заменяет
«Партнёр кодер» или конкурирует с ним.

**Плюсы:**

- код остаётся публичным для аудита и доверия;
- можно принимать внешние исправления;
- проще объяснить сообществу;
- не требует раскрывать коммерческие детали.

**Минусы:**

- это не OSI-лицензия;
- нужно юридически определить «конкурента»;
- клиенты могут захотеть отдельные коммерческие условия.

**Когда подходит:** если репозиторий остаётся публичным, а коммерческая
ценность — в сервисе, поддержке и бренде.

## 2. Proprietary EULA

**Что разрешает:** только использование по договору с правообладателем.

**Плюсы:**

- максимальный контроль;
- привычная модель для корпоративных клиентов;
- проще ограничить перепродажу и конкурирующие сервисы.

**Минусы:**

- публичный репозиторий теряет смысл;
- меньше доверия и внешнего аудита;
- сложнее привлекать контрибьюторов;
- нужен отдельный EULA и договор.

**Когда подходит:** если код должен быть закрыт, а публичный репозиторий —
только витрина.

## 3. Рекомендация

Для текущей стратегии публичного source-available репозитория
рекомендуется **PolyForm Shield 1.0.0** плюс отдельные коммерческие условия
для клиентов. Окончательное решение — с юристом.

## 4. Что сделать после решения

- заменить `LICENSE` утверждённым текстом;
- обновить `README.md`, `CONTRIBUTING.md` и `docs/index.md`;
- указать, какие права получает клиент по договору подписки;
- проверить совместимость с зависимостями;
- добавить уведомление о товарном знаке «Партнёр кодер».
