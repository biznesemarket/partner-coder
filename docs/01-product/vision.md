# Видение продукта

## 1. Проблема

- Директор не понимает реальную стоимость разработки с ИИ и не может честно
  объяснить команде, как считается вознаграждение.
- Почасовой учет «сидел за компьютером» не отличает активную работу человека
  от автономной работы агента и легко накручивается.
- Обещания доли «на словах» создают споры: нужен прозрачный воспроизводимый расчет.
- Вендор не может продавать продукт, если каждый клиент требует терминала,
  ручной настройки сервера и сопровождения.
- Клиенту нужен ежедневный контроль, а не отчет раз в месяц.

## 2. Решение

1. Вендор продает подписку и выдает клиенту zip-пакет с одноразовым ключом.
2. Директор открывает папку в ИИ-клиенте; ИИ через MCP проводит онбординг без терминала.
3. Разработчики работают как обычно; MCP-сервер и расширение IDE фиксируют
   сессии и активность (только метаданные).
4. В 00:00 по часовому поясу проекта система закрывает день: классы времени,
   коэффициенты, капы, ставка, рубли, доля.
5. Утром разработчик получает дайджест от своего ИИ; директор видит сводку и
   флаги; суперадминистратор — оплаты и здоровье клиента.
6. Любую цифру можно разложить: интервалы, классы, капы, версии политики,
   корректировки.
7. Начисления неизменяемы; изменения — только компенсирующими записями с аудитом.

## 3. Ключевая граница

«Доля» — расчетный процент вклада (фантомная доля), а не юридическая доля в
ООО и не ценная бумага. «Начислено» и «выплачено» всегда разделены. Платформа
не проводит платежи разработчикам в MVP.

## 4. Для кого

| Роль                       | Что получает                                                |
| -------------------------- | ----------------------------------------------------------- |
| Суперадминистратор вендора | клиенты, счета, оплаты, пакеты, воронка, лимиты, аудит      |
| Директор клиента           | дашборд «Сегодня», политика, команда, флаги, споры, выплаты |
| Разработчик                | дайджест «Мой день», прозрачная раскладка, пауза, спор      |
| ИИ-ассистент               | MCP-инструменты онбординга, сессий, дайджеста и диагностики |

## 5. Первый релиз (вертикальный срез)

Один клиент, один проект, 2–3 разработчика, полный цикл закрытия дня на
Windows. macOS/Linux, юридический модуль, эквайринг и self-host — после пилота.

## 6. Критерии успеха

| Горизонт | Критерий                                                                 |
| -------- | ------------------------------------------------------------------------ |
| M1       | Все golden-тесты совпадают до копейки и до единицы доли                  |
| M3       | Суперадмин проводит клиента от счета до пакета без БД                    |
| M4       | Директор на чистой Windows проходит онбординг без терминала в 3 клиентах |
| M6       | 3 разработчика, 5 дней, корректные закрытия и дайджесты                  |
| M8       | Разработчик видит вчера/всего; директор отмечает выплату; отчеты         |
| M10      | Пилот подписан; 5+ дней; нет ручных правок БД; ретро                     |
| Бизнес   | Первый клиент оплатил подписку; второй клиент в воронке                  |
