скидки и правила биллинга.

Период оплаты — один месяц. Годовой оплаты и онлайн-эквайринга в MVP нет.

### 1.1 Что считается рабочим местом

Одно рабочее место — это один активный разработчик. На одно место
действует:

- одно зарегистрированное устройство;
- одна активная MCP-сессия;
- неограниченный объём метаданных в рамках технических rate limit;
- без хранения кода, промптов, файлов и скриншотов.

Дополнительные места, проекты и репозитории сверх тарифа — только по
индивидуальному решению суперадминистратора. Автоматического доплатного
расширения в MVP нет.

## 2. Статусы подписки

| Статус      | Что означает                           | Доступ                               |
| ----------- | -------------------------------------- | ------------------------------------ |
| `trial`     | Бесплатный пробный период              | Полный, с лимитами тарифа «Пилот»    |
| `active`    | Оплаченный период                      | Полный                               |
| `grace`     | Льготный период после окончания оплаты | Полный, с предупреждением            |
| `expired`   | Оплата не поступила, период закончился | Только чтение, продление и поддержка |
| `suspended` | Принудительная приостановка            | Только биллинг и поддержка           |

Сроки:

- `trial` — 14 дней, 3 места, 1 проект;
- `grace` — 7 дней после `period_end`;
- `expired` — до 30 дней, затем `suspended`;
- `suspended` — вручную суперадминистратором; данные хранятся по политике
  retention.

Переходы:

```text
trial   -> active       после оплаты
trial   -> expired      после окончания trial
active  -> grace        после period_end
active  -> suspended    вручную суперадминистратором
grace   -> active       после оплаты и продления
grace   -> expired      после grace_until
expired -> active       после оплаты и продления
expired -> suspended    после 30 дней без оплаты
suspended -> active     после оплаты и решения суперадминистратора
```

Автоматическое отключение при окончании оплаченного срока выполняется
системой: `active -> grace -> expired`. Ручное продление делает бухгалтер
через роль `finance`.

## 3. Скидки и индивидуальные условия

- Скидка от 10% до 50%.
- Только ручное назначение суперадминистратором.
- У скидки есть дата начала и дата окончания.
- Одна активная скидка на подписку; автоматического суммирования нет.
- Скидка отображается в счёте и фиксируется в аудите.
- Индивидуальные условия оформляются так же, как скидка, и фиксируются в
  комментарии к подписке.
- Возвраты не предусмотрены. Исключение — только после решения юриста и
  бухгалтерии, вручную суперадминистратором.
- Списания (write-off) без решения юриста не делаются.

## 4. Счета и платежи

- Клиент платит банковским переводом по счёту.
- Счёт формирует и подписывает бухгалтерия.
- Нумерация, обязательные поля, закрывающие документы и учёт частичных
  оплат — ответственность бухгалтерии.
- В системе бухгалтер работает через роль `finance`: создаёт счёт, вносит
  оплату, продлевает оплаченный период.
- Онлайн-платежи и карты в MVP не подключаются.

## 5. Роли и права

| Действие                         |        `superadmin`         | `finance` | `support` | `readonly` |
| -------------------------------- | :-------------------------: | :-------: | :-------: | :--------: |
| Клиенты: создание/редактирование |             да              |    нет    |    нет    |    нет     |
| Клиенты: просмотр                |             да              |    да     |    да     |     да     |
| Тарифы: изменение                |             да              |    нет    |    нет    |    нет     |
| Тарифы: просмотр                 |             да              |    да     |    да     |     да     |
| Счёт: создание/отправка          |             нет             |    да     |    нет    |    нет     |
| Счёт: просмотр                   |             да              |    да     |    да     |     да     |
| Платёж: внесение                 |             нет             |    да     |    нет    |    нет     |
| Подписка: продление/статус       |             нет             |    да     |    нет    |    нет     |
| Скидка: назначение               |             да              |    нет    |    нет    |    нет     |
| Приостановка клиента             |             да              |    нет    |    нет    |    нет     |
| Возврат/списание                 | только после решения юриста |    нет    |    нет    |    нет     |
| Пакет: перевыпуск                |             да              |    нет    |    да     |    нет     |
| Аудит: просмотр                  |             да              |    да     |    да     |     да     |

«Бухгалтер» в терминах системы — роль `finance`.

### 5.1 Step-up

Дополнительное подтверждение паролем требуется для:

- создания и отправки счёта;
- внесения платежа;
- продления подписки и смены оплаченного периода;
- назначения скидки;
- приостановки клиента;
- возврата/списания после решения юриста.

## 6. Утверждено

1. Trial — 14 дней; grace — 7 дней; expired read-only — 30 дней; suspended —
   вручную.
2. Лимиты: проекты 1/3/10, репозитории 2/5/20, повторная выдача пакета
   1/3/fair use, сброс enrollment 1/3/fair use.
3. `support` может перевыпускать пакет и сбрасывать enrollment, но не менять
   деньги и финансовые статусы.
4. Резервного суперадминистратора нет. Восстановление — break-glass через
   владельца БД по `docs/07-ops/break-glass.md`; это аварийная процедура, а не
   постоянный второй администратор.
