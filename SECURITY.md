# Политика безопасности

## Поддерживаемые версии

Продукт в стадии подготовки пилота. Исправления безопасности выпускаются для
последней версии `main`.

## Как сообщить об уязвимости

**Не создавайте публичный issue с описанием уязвимости.**

1. Напишите на `security@pcoder.ru` (адрес будет подтвержден до пилота).
2. Укажите: версию/коммит, шаги воспроизведения, влияние, вектор атаки.
3. Ожидайте подтверждения получения в течение 2 рабочих дней.

Мы подтверждаем получение, согласуем срок исправления и публикуем сводку
после релиза. Не публикуйте детали до нашего согласия.

## Область действия

В области: API и веб-кабинеты, изоляция tenant, аутентификация и токены,
MCP-сервер и агент, обработка вебхуков, расчет начислений.

Вне области: атаки на инфраструктуру облачного провайдера, социальная
инженерия, DoS без значимого влияния, уязвимости сторонних зависимостей без
подтвержденного эксплойта (сообщите отдельно).

## Правила для контрибьюторов

- Никогда не коммитить секреты, ключи, токены, `.env`, персональные данные.
- Не логировать PII, токены, содержимое кода и промптов.
- Любая работа с чужим tenant — только через RLS и проверку прав.
- Опасные действия (выплаты, политика, споры) — с аудитом и подтверждением.
- Подозрение на утечку — немедленно сообщить сопровождающему и остановить
  публикацию.

## Проверки

- Secret scanning и dependency review в CI.
- CodeQL для TypeScript.
- CodeQL/SAST дополняется пентestом перед пилотом (M9).
- Зависимости обновляются через Dependabot; lockfile коммитится.
