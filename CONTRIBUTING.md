# Как участвовать

## Перед началом

1. Прочитайте `AGENTS.md` и `docs/05-process/development-process.md`.
2. Прочитайте `docs/02-domain/time-accounting.md` и `docs/02-domain/economics.md`:
   расчет — ядро продукта.
3. Проверьте, что задача есть в issue с критериями приемки.

## Локальная проверка

```bash
pnpm install
pnpm check        # prettier + eslint + typecheck + unit/golden/property
```

Ожидается: все тесты зеленые, включая 20 golden-сценариев.

## Ветки и коммиты

- Ветка: `feat/<issue>-<кратко>`, `fix/...`, `docs/...`, `chore/...`.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- Изменения расчета — только с ADR, обновленной спецификацией и golden-фикстурой.

## Pull request

Шаблон PR требует:

- что изменено и зачем;
- как проверено (команды и результат);
- влияет ли на расчет (и если да — ссылка на ADR);
- нет ли секретов и PII;
- чек-лист Definition of Done.

## Ревью

- Ревьюер не автор. При одном сопровождающем разрешен self-merge при зеленом
  CI и 0 approvals (временное исключение).
- Замечания по существу: «это сломает инвариант 6» лучше, чем «переименуй».

## Стиль

- TypeScript strict, без `any` в публичных API.
- Доменная логика — только в `packages/domain`; приложения ее не дублируют.
- Русский язык — для UI, документации и сообщений об ошибках; английский — для
  имен кода и коммитов.

## Что не принимается

- Изменение формул без ADR.
- Отключение проверок CI.
- Секреты, ключи и данные клиентов в репозитории.
- «Временные» обходы изоляции tenant.
